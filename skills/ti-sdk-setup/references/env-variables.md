# Variables exported by scripts/ti-sdk-env.sh

Source: `scripts/ti-sdk-env.sh`, run against three SDKs on disk (see the end). Values shown as examples
carry their evidence. Nothing here is a default: the SDK is the authority.

| Variable | Source | Notes |
|---|---|---|
| `TI_SDK_ROOT` | `$TI_SDK_ROOT`, `$PROCESSOR_SDK_LINUX`, or walk up from cwd | A directory with `Rules.make` and `board-support/` |
| `TI_SDK_VERSION` | trailing version token of the SDK directory name, `_` turned into `.` | e.g. directory `...-12.02.00.01.01` gives `12.02.00.01.01`; `...-12_01_00_09` gives `12.01.00.09` |
| `TI_SDK_VERSION_DOCS` | same token, `.` turned into `_` | Form used by `ti_processor_sdk_docs_list_versions` |
| `TI_SOC` | `SOC` in Rules.make | SoC family key from the SDK; not unique per board, prefer `TI_PLATFORM` for file lookups |
| `TI_PLATFORM` | `PLATFORM` | Directory name under `board-support/prebuilt-images/` and `filesystem/` (example from AM62P SDK 12.02.00.01.01: `am62pxx-evm`; some SDKs differ, check with `ls`) |
| `TI_ARCH` | `ARCH` | |
| `TI_UBOOT_MACHINE`, `TI_UBOOT_MACHINE_R5` | `UBOOT_MACHINE`, `UBOOT_MACHINE_R5` | R5 is empty when Rules.make has none (e.g. the AM335x RT SDK checked) |
| `TI_DTB_PREFIX` | `KERNEL_DEVICETREE_PREFIX` | Regex-like list used by `makerules/Makefile_linux-dtbs` to pick DTBs |
| `TI_CROSS_COMPILE` | `CROSS_COMPILE` (expanded by make) | Prefix; append `gcc` |
| `TI_CROSS_COMPILE_R5` | `CROSS_COMPILE_ARMV7` | Empty if the SDK has no R5 toolchain |
| `TI_KERNEL_SRC_DIR`, `TI_UBOOT_SRC_DIR` | `LINUXKERNEL_INSTALL_DIR`, `UBOOT_SRC_DIR` | Globs under `board-support/` expanded by make |
| `TI_KERNEL_VERSION` | `software_manifest.txt` row whose first column is `kernel` | The manifest has no SDK version row; the SDK version comes from the directory name |
| `TI_DOCS_DEVICE` | derived by the library from `PLATFORM`, a docs MCP key | Check it against `ti_processor_sdk_docs_list_variants`; empty if not derivable (then ask the user) |
| `TI_FACTS_DIR`, `TI_KB`, `TI_FACTS_JSON` | generated by the `ti-generate-kb` skill (its `scripts/gen-sdk-facts.py`) | `TI_KB` = `<platform>.md`, `TI_FACTS_JSON` = `<platform>.json` in `TI_FACTS_DIR`; empty until generated |

Facts the library does not export (boot files, DT model, remote cores, reserved memory, top-level
make targets) come from `$TI_KB` / `$TI_FACTS_JSON`. If they are empty, run `ti-generate-kb`.

Tested (this repo, 2026-10-12, `check-sdk.sh` on each SDK; examples): the AM62P 12.02.00.01.01 SDK populates every
`Rules.make` variable; the AM335x RT 12.02.00.01.01 SDK has no R5 toolchain or kernel version row; the
TDA54 ADAS 12.01 SDK has no `UBOOT_MACHINE_R5` and no `prebuilt-images/<platform>`. The library
prints a warning for each missing value and does not fail.
